# Runtime v2026.10.22.1 upgrade notes

## Who needs to act

Deployments and client repositories that run or integrate
`liki-agent-runtime` must review two behavior changes before rolling this
image out:

1. readiness, version, and metrics no longer share the protocol listener;
2. direct-connect deployments can enable mutual TLS and signed completion
   callbacks.

## Operational listener migration

The operational surface now runs on a dedicated listener:

| Surface | Endpoints | Default address |
| --- | --- | --- |
| Protocol | A2A, AG-UI, MCP, agent card | `LIKI_AGENT_RUNTIME_ADDR`, default `:8083` |
| Operations | `/readyz`, `/version`, `/metrics` | `LIKI_AGENT_RUNTIME_OPS_ADDR`, default `:8085` |

Update container health checks, orchestrator probes, metrics scrape targets,
port mappings, and network policies to use the operations address. The built-in
`healthcheck` subcommand already follows `LIKI_AGENT_RUNTIME_OPS_ADDR`.

Do not point both listeners at the same address; startup fails closed if the
addresses collide.

## Direct-connect mutual TLS

Mutual TLS is optional. Configure all four values, or none:

```bash
LIKI_AGENT_RUNTIME_TLS_ADDR=:8084
LIKI_AGENT_RUNTIME_TLS_CERT=/pki/server.crt
LIKI_AGENT_RUNTIME_TLS_KEY=/pki/server.key
LIKI_AGENT_RUNTIME_TLS_CLIENT_CA=/pki/client-ca.pem
```

The mTLS listener requires and verifies a client certificate. On this trusted
channel, the runtime accepts `Remote-User` as the caller identity and treats
the client certificate as the channel credential. It rejects the legacy
`X-Liki-User-ID` header on mTLS requests.

The plaintext relay listener keeps using the internal bearer token and
`X-Liki-User-ID`; it ignores `Remote-User`.

## Run completion callbacks

A direct-connect run can notify the control plane when it reaches a terminal
state. Callbacks are disabled unless both values are configured:

```bash
LIKI_AGENT_RUNTIME_CALLBACK_URL=https://control-plane.example/api/internal/runs/completed
LIKI_AGENT_RUNTIME_CALLBACK_SECRET=whsec_...
```

The payload is a CloudEvents structured message signed with Standard Webhooks.
Only runs received on the mTLS listener emit callbacks. Relay runs remain
owned by the existing web persistence path and do not emit duplicate callbacks.

## Rollout checklist

- [ ] Probe `/readyz` on `LIKI_AGENT_RUNTIME_OPS_ADDR`.
- [ ] Scrape `/metrics` on the operations address.
- [ ] Expose or allow the operations listener on internal networks only.
- [ ] Update published protocol URLs if they assumed `/readyz` and `/version`
      lived on the protocol port.
- [ ] Install the server certificate, key, and trusted client CA before
      enabling `LIKI_AGENT_RUNTIME_TLS_ADDR`.
- [ ] Configure and verify Standard Webhook signature checking before enabling
      completion callbacks.
- [ ] Keep the plaintext relay path available until direct-connect traffic and
      callback persistence are verified.
